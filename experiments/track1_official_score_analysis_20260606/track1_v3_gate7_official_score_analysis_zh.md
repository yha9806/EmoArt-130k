官方公式是 `Overall = 0.5 * FID Score + 0.5 * AAS`。我们的可见计算为 `(0.55 + 0.98) / 2 = 0.765`，页面四舍五入为 `0.77`。

## 这次结果说明什么

1. **7 张微修对 FID 几乎没有统计重量。**  
   FID 是 1000 张集合的分布指标。替换 7 张，即使每张都更好，也很难让全局 FID 从 `80.92` 移到 `66-70` 区间。

2. **placeholder 修复没有变成可见 AAS 提升。**  
   这不代表修错了，而是 4 张硬伤在 1000 张平均里最多也只影响千分位级别。页面 AAS 只显示两位小数，细微改动会被吞掉。

3. **AAS 不是当前最大瓶颈。**  
   我们 `AAS=0.98`，冠军 `0.99`。AAS 还有一点空间，但只靠 AAS 不可能冲到 `0.80`：如果 FID Score 仍是 `0.55`，理论上 AAS 要到 `1.05` 才能 overall 到 `0.80`，不可能。

4. **冲第一必须把 FID 拉下来。**  
   第一、第二名的共同结构是 `FID≈66`、`FID Score=0.60`、`AAS=0.99`。我们需要把 FID 从 `80.92` 降到大约 `66-70`，同时 AAS 不低于 `0.98-0.99`。

## 分数目标

| 假设 | 需要的 FID Score | 解释 |
|---|---:|---|
| AAS 保持 `0.98`，想显示 `0.79` | `0.60` | `(0.60 + 0.98) / 2 = 0.79` |
| AAS 保持 `0.98`，想显示 `0.80` | 约 `0.61` | 页面四舍五入到 `0.80` 需要接近 `0.795` |
| AAS 提到 `0.99`，想显示 `0.80` | `0.60` | 这正是当前前两名结构 |

因此下一阶段不能再以“小规模人工挑图”为主线。正确方向是：用本地 FID/style-family 代理选择一批更大的、分布上更接近官方参考集的候选包，再用 AAS gate 防止内容崩。

## 对 v3 gate7 的判定

v3 gate7 是一个有效的安全探针，但不是冲奖方案：

- 它证明：修 placeholder + 少量高置信替换不会明显伤榜单。
- 它也证明：这种规模不可能解决 FID。
- 它没有证明：我们的 reference-grounded / Vulca pipeline 足够接近强队。

保留 v3 gate7 作为“干净 baseline”是合理的，但下一次提交应当测试更大规模分布包，而不是继续只加几个单点修复。

## 下一步建议

1. **先做本地 FID/style-family sweep。**  
   比较 v1、v3 gate7、full1000 official-v7、Top50/Top200 不同替换比例下的 Inception/FID-like、颜色/纹理/尺寸分布和 style-family 覆盖。

2. **生成 v4 FID-balanced 包。**  
   目标不是“所有候选看起来更漂亮”，而是让 1000 张整体分布更像 official reference set。候选替换规模应进入 `100-300` 张量级，否则 FID 很难动。

3. **加 AAS hard gate。**  
   任何大规模 FID 包必须守住 caption 内容、surface/support、文字、旗帜/地标、关系逻辑。目标是 FID 降，AAS 不低于 `0.98`。

4. **下一次 Codabench 提交优先测 v4 broad package。**  
   如果 v4 把 FID Score 从 `0.55` 拉到 `0.57-0.58`，就说明方向对；如果 AAS 掉到 `0.96` 以下，说明替换过宽，需要收紧 gate。

5. **不要再把 v3 gate7 结果解读成 Vulca 无效。**  
   这次只是改动太少，无法影响分布指标。Vulca 的价值应该转到 prompt compiler、reference routing、surface/relationship gate 和 AAS 守门，而不是靠 7 张图改变 FID。

## 当前判断

我们现在是第二梯队头部附近，但还不是冲第一状态。要拿奖，必须把工作重点从“单图修错”切到“全量分布校准 + 大规模候选替换 + AAS 防守”。下一次真正有信息量的提交应该是 v4 broad FID-balanced 包，而不是 v3 gate7 的小幅延伸。
